# E7.62 — Minimal Specialized Self-Evolving Core

## Objective

Define the commercial delivery unit as a minimal, strictly bounded, self-evolving Core specialized for one partner/project domain.

## Composition

A partner Core consists conceptually of:

Core_minimal + DomainKnowledge + PartnerConstraints + EvolutionContracts

The common Core remains the source of the minimal evolution mechanics. Domain knowledge and partner constraints remain scoped to the partner/project unless explicitly authorized for broader learning.

## Required properties

The delivered Core MUST:
- preserve the canonical Ψ-Core invariants;
- operate only within its declared domain/scope;
- retain provenance for learned knowledge;
- preserve partner data boundaries;
- use governed evolution;
- reject unauthorized capability escalation;
- distinguish learned knowledge from authority;
- remain independently auditable through its contract/evidence package.

## Network learning

A partner Core MAY contribute generalized findings to Common Self-Learning only through the governed promotion path. Private source data MUST NOT be copied into shared learning without explicit authorization.

## Delivery

The commercial deliverable is the specialized Core plus its contract/evidence package, not unrestricted access to the proprietary Common Core implementation.
