# E8.03 — Self-Analysis & Improvement Proposal

## Generated analysis

Current self-learning modules establish boundaries for memory admission, cycle re-entry, input isolation, opportunity classification, reclassification and contract formation. The current implementation, however, leaves these boundaries largely as independent functions. The highest-value improvement is therefore a deterministic orchestration boundary that consumes the preceding evidence chain and emits one auditable contract proposal.

### Observed architectural gaps

1. No end-to-end chain object connects admitted Evolution Memory → Learning Cycle → Learning Input → Opportunity → Reclassification → Contract Candidate.
2. Opportunity classification and contract formation can be called independently, so the contract layer does not yet prove that its input came from the current learning cycle and evidence boundary.
3. Commercial financial evidence is checked at contract formation but is not represented as a first-class typed evidence category.
4. Reclassification records evidence but does not verify continuity with the original Opportunity evidence set.
5. There is no persistent proposal artifact containing the complete reasoning/provenance chain needed for human review and later replay.

## Proposed improvement

Implement E8.03 — Auditable Self-Improvement Proposal as the next contract.

The proposal object should bind:

memory_entry → cycle → learning_input → opportunity → classification/reclassification → contract_candidate

and contain a deterministic proposal ID, source/evidence references, scope/confidentiality, value level, financial evidence when commercial, contract kind, rationale, expected result, acceptance conditions, unresolved gaps, status and provenance digest.

## Expected result

The Core should be able to produce a machine-readable, reviewable proposal for improving itself or for opening a research/open/commercial project, without granting itself execution authority.

## Acceptance criteria

- Missing provenance link blocks proposal formation.
- Partner-private evidence cannot enter a different scope.
- Commercial proposal without financial evidence is rejected.
- Proposal ID is deterministic for identical inputs.
- Proposal contains all upstream evidence references.
- Proposal generation cannot mutate Core state or grant execution authority.
- Identical inputs produce the same proposal digest.
